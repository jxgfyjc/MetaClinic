# 象元 AI 诊疗：权限隔离与完整诊疗闭环修复

基于现有项目增量开发，不推倒重写。当前重点不是增加新功能，而是让患者端、医生端彻底隔离，并真正完成从患者登记到医生确认诊疗结果、保存及导出的全流程。

## 1. 患者与医生端严格隔离（最高优先级）

当前患者扫码提交资料后，仍能通过「查看就诊详情」或右上角「医生端」按钮进入医生界面，必须彻底修复。

- 患者端只允许访问自己的资料提交、上传、提交状态及被授权查看的患者功能。
- 移除患者页面中通往医生端的入口，但不能只靠隐藏按钮实现安全。
- 后端所有医生页面对应的 API、AI 结果、全部患者查询、诊断、处方、审核、签名、导出接口都必须进行服务端身份认证和角色授权。
- 患者即使手动修改 URL、伪造请求、替换患者 ID 或直接调用 API，也不得访问医生功能及其他患者的数据。
- 患者扫码令牌只用于提交资料，不得等同于医生登录凭证。
- 医生端必须有独立登录和授权校验；未登录或权限不足时，页面和 API 均拒绝访问。
- 为关键操作记录操作者、时间和审计事件。

必须实际测试：患者点击链接、直接输入医生端地址、直接调用医生 API、替换患者 ID 均不能越权。不能仅以 UI 上没有按钮作为验收结果。

## 2. 患者提交后自动启动 AI 预分析

患者通过医生专属二维码提交症状、语音、检验报告和舌象后：

提交成功 → 创建正式患者/就诊关联记录 → 保存附件 → 自动启动后台 AI 预分析。

要求：

- 患者提交后无需医生手动点击分析。
- 患者端不展示内部 AI 推理结果、诊断候选、处方候选或医生内部审核状态，只展示资料提交成功和必要的处理状态。
- 自动执行现有 ASR、OCR 及相关分析；有对应输入才调用相应模块，不能因为缺少图片就使用默认图片。
- 中西医分析、综合分析和可预生成的处方草稿在后台异步执行。
- 所有输出、模块状态、错误与耗时真实持久化。
- 同一次提交不得重复创建任务。失败可重试，重试不能重复生成患者或就诊记录。
- 若资料不足，保存已经取得的结果，并明确标记缺失信息，不能假装全部分析完成。

## 3. 医生打开患者时立即看到已有分析

医生打开待接诊列表或患者档案时，应优先加载已经持久化的最新 AI 预分析结果，而不是再次启动整套分析。

- 展示西医分析、中医辨证、风险提示、检验结果摘要及综合方案草稿。
- 显示分析状态、完成时间、失败模块和待补充信息。
- 已完成的运行直接读取数据库，不重新调用模型。
- 资料发生变化时，将旧结果标记为待更新或过期，再启动新一轮分析。
- 医生可以主动重新分析，但必须保留历史运行记录。

## 4. 先确认诊断，再快速形成唯一综合处方

AI 可以提前生成与候选诊断关联的处方草稿，以减少医生实际接诊时的等待，但所有候选都必须标记为未确认草稿。

医生接受、修改或驳回诊断后：

- 根据医生最终选定的诊断，立即展示对应的预生成方案。
- 若已有草稿与最终诊断不匹配，重新生成或更新，不得直接复用错误方案。
- 最终只形成一份整合西医与中医分析的综合诊疗方案，不要产生互相割裂、重复用药的两套最终处方。
- 支持医生对药物、饮片、剂量、克数、频次、剂数、疗程及治疗项目进行新增、修改、删除。
- 所有修改都必须保存到后端，刷新页面后仍然存在。

## 5. 修复综合治疗方案的接受、修改、驳回

此前推拿、针灸、理疗建议生成后的按钮没有真正生效，需要逐一检查前端事件、API 请求、数据库更新和重新加载结果。

每项治疗建议必须具有明确状态：

`AI_GENERATED → ACCEPTED / EDITED / REJECTED`

修改时保存原始内容、修改后内容、操作者和时间。接受后纳入综合诊疗草稿；驳回后从待执行方案中排除，但保留审计记录。

推拿、针灸、艾灸、理疗和康复建议应使用独立的治疗项目结构，允许记录具体穴位、手法、操作方式、频次、疗程和禁忌。信息必须有知识依据，并由医生最终确认。

## 6. 最终诊断必须形成完整、可保存和可导出的记录

目前流程似乎停留在 AI 分析阶段，需要建立真正的「最终诊疗记录」，而不是只保存 AI Run。

医生完成确认后，将以下内容统一保存：

- 患者及本次就诊信息
- 主诉、现病史、既往史、过敏和检验结果
- 医生确认的中西医诊断与辨证结果
- 医生最终确认的综合治疗方案
- 最终处方明细及药物剂量
- 推拿、针灸、理疗等治疗项目
- 医生修改、审核、签名与确认时间
- 复诊、随访计划及必要的审计信息

新增或完善「诊疗记录详情」页面，支持重新打开历史记录，而不必重新运行 AI。

提供完整诊疗记录导出，优先实现可打印的 PDF；导出内容必须与数据库中的最终确认记录一致，不能直接把 AI 原始输出当作正式病历。记录尚未确认时，应明确标记为草稿。

## 7. 全链路验收

使用一个全新的虚构病例实测：

患者扫码 → 提交症状、语音和检查报告 → 后台自动预分析 → 患者无法访问医生端 → 医生登录后立即看到预分析结果 → 确认诊断 → 获取对应综合处方 → 修改药物及推拿理疗方案 → 确认并保存 → 导出完整诊疗记录 → 创建随访。

此外必须验证：

- 患者直接访问医生路由和 API 均被拒绝。
- 页面刷新或 API 重启后结果仍在。
- 已有 AI 结果不会无故重新生成。
- 接受、修改、驳回按钮会真实修改持久化状态。
- 模型失败不会导致患者资料丢失。
- 同一就诊重复提交不会造成重复记录或重复收费。
