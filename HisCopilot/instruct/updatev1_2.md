# 临床智能体增强：上传闭环、诊断联动、个性化经验与随访

你是本项目的 Senior AI Architect。基于现有代码增量开发，不推倒重写。先检查现有实现，对以下功能逐项审计：已实现、部分实现、未实现；然后修复缺口并运行端到端测试，不要把已有功能重复开发。

### 1. 舌象与检验报告必须使用真实上传文件

验证前端上传、文件存储、后端读取、模型输入和结果展示的完整链路。不得使用默认图片、固定路径或预置结果冒充用户上传。

图片上传后立即预览、显示进度并关联本次就诊。为模型推理生成适当尺寸的压缩副本，同时保留原始图片供医生查看，避免因压缩丢失关键细节。无图片时标记为 `SKIPPED`，真实处理失败才标记 `FAILED`。

检验 OCR 的结构化结果必须进入临床上下文，展示项目名、数值、单位、参考范围及原报告来源，并允许医生校对。明确记录识别结果实际被哪些分析模块使用。

### 2. 接受、反驳、修改必须同步诊断记录表单

将 AI 候选、医生审核结果、最终诊断与处方草稿统一关联到当前就诊。

医生点击接受、反驳或修改后，立即持久化并更新界面中的诊断结果表单。表单应包含西医诊断、中医证型、主要依据、治疗目标、医生修改记录和当前审核状态。

**只有医生接受并选定某个目标诊断后，才针对该诊断异步生成对应的开方草稿。** 不要把多个不同诊断的药物混在一个处方中。中西医模式应明确区分；需要针对另一个诊断开方时，创建独立草稿。

### 3. 建立可编辑的药品库与处方表单

药品库支持数百种药品的搜索、筛选、选择及 CSV 导入，字段至少涵盖通用名、规格、剂型、单位、用法、来源和院内编码。

优先使用医院真实药品目录；没有目录时可使用明确标识的演示字典，不能伪造院内编码或实际库存。中药饮片需支持药味、克数、剂数及煎服信息。

医生可在处方表单中新增、修改和删除药物，也可以手动补充 AI 未推荐的项目。修改应实时更新前端状态并持久化。剂量和频次不能仅凭模型输出视为已验证信息。

### 4. 实现真正的双向周期随访

医生根据本次诊疗创建随访计划，设置日期或周期。系统提醒患者填写服药依从性、症状变化、不良反应和相关指标。

患者提交后，结果自动进入医生端待处理列表和患者时间线，触发摘要、风险评估与医生处理流程。医生的回复和下一次随访安排也应返回患者端。

第一阶段可以使用系统内通知；短信或微信未接入时必须明确显示未配置，不得假装已发送。

### 5. 让医生个人经验从历史病例中形成

增加批量上传历史诊断、病历、处方及图片/PDF 的入口。先完成 OCR 与病例结构化，再按疾病、症状、证型、诊断、药物组成、克数和治疗方法归类。

重点提炼具体临床思路，而不仅是学术流派。例如某位医生处理失眠时，是否反复考虑脾胃、饮食与兼证；面对相似病例时，哪些辨证路径、方药组合和加减规律反复出现。

每条归纳规律必须能追溯到原始病例，并显示样本量、适用条件、例外和不确定性。使用相似病例检索、规律归纳和医生审核来形成个人画像，先不训练模型。

采用分批异步处理：先用约 10–20 份经过脱敏的病例验证结构化质量，再扩展到约 100 份，记录实际处理耗时。所有风格总结必须由医生确认后才能用于后续诊疗。

### 6. 每位医生生成专属患者二维码

为每位医生提供专属二维码。患者扫码进入手机端问诊页面，输入文字或语音、上传检验报告和舌象，并提交自己的病情资料。

提交后自动绑定医生和就诊请求，写入数据库，触发初步 AI 分析。医生打开待接诊列表时，应能查看患者资料、附件、初步分析状态及已经完成的结果。

二维码只包含必要的访问路由或安全令牌，不包含患者病历等敏感信息。做好基本防滥用和访问校验。局域网测试时明确显示手机实际访问地址，不能把服务器端 `localhost` 当作手机 API 地址。

### 7. 诊断耗时与智能体架构

对同一次 AI Run 记录上下文准备、OCR、RAG、西医、中医、综合分析、处方生成、校验及持久化耗时。当前完整冷运行约 240 秒，不能未经测量就认定处方阶段是瓶颈。

审计现有 Orchestrator，并评估 LangGraph 等 Agent Harness 是否适合承载动态规划、工具选择、结果观察、重规划、状态恢复和人工审核。先复用现有模型与工具，制作最小验证，不全面迁移业务代码。

Agent 可以自主选择分析和检索步骤，但不能绕过医生确认执行正式处方或 HIS 操作。

### 8. 最终验收

使用全新虚构病例，验证：

患者扫码 → 输入症状及语音 → 上传检查单和舌象 → 自动建立就诊并触发初步分析 → 医生查看结果 → 接受或修改一个目标诊断 → 异步生成对应处方 → 增删改药物 → 保存诊断与处方 → 创建随访 → 患者回复 → 医生收到更新。

另行验证图片确实送入模型、OCR 结果确实影响分析、两份医生画像能对同一病例形成有依据的差异，以及 API 重启后数据仍然存在。
