# 任务：将现有 AI 中西医门诊辅助系统收敛为一个完整可演示的端到端 MVP

## 一、当前目标

当前项目已经具备：

* FastAPI 后端
* Next.js 前端
* 本地 Qwen 临床模型
* 本地 ShizhenGPT 中医模型
* OCR、ASR 等已配置模型服务
* AI Orchestrator
* Mock HIS
* AI 分析、处方草稿及随访的基础流程

本轮目标不是继续建设完整的生产级系统，而是：

**使用最少必要的工程改动，完成一条可重复运行、状态真实、界面连贯的端到端门诊演示流程。**

不推倒重写，不增加新模型，不修改现有 ComfyUI 和 aivideo。

## 二、严格保护现有环境

1. 保留现有 Anaconda 环境及 GPU 分配。
2. 不修改端口 8000、8188 上的既有服务。
3. 不下载新模型，不训练模型。
4. 不向公网发送医疗数据。
5. 继续调用真实本地模型，不允许用硬编码 JSON 或假 AI 结果冒充模型推理。
6. 先阅读现有代码和运行说明，能复用的直接复用。
7. 所有新功能必须实际运行和测试，不得以生成代码代替完成验收。

## 三、只实现一条黄金路径

使用一个虚构 Demo 患者，完整完成：

患者输入病情
→ 上传检验报告
→ 上传舌象
→ 医生打开接诊工作台
→ 真实 AI 分析
→ 医生接受、修改或驳回建议
→ 编辑并保存病历
→ 审核处方草稿
→ 演示签名
→ 提交 Mock HIS
→ 创建随访
→ 模拟患者回答
→ 高危回答进入医生预警列表。

如果某项输入模型已经可以正常使用，就接入真实服务；如果现有接口存在缺陷，优先修复现有接口，不要重新实现另一套服务。

## 四、先保证关键数据持久化

检查真实 ORM Schema，只为黄金路径涉及的实体建立或完善数据访问逻辑。

至少确保：

* 患者
* 就诊
* 医疗文书
* 检验结果
* AI 运行与模块输出
* 处方草稿及审核状态
* 随访计划和回答
* 风险预警
* 审计记录

可以复用现有 MockHISAdapter，但不要只把数据保存在进程内存中。

提供一个幂等的 Demo 初始化脚本。重复运行不能不断追加患者和历史记录，也不能覆盖医生已经编辑的病历。

重启 API 后，以上关键业务记录必须仍能查询。

无需本轮接入全部 22 张 ORM 表，也无需为了统一架构而大规模重构 Repository。

## 五、医生工作台

以现有 `/encounters/enc-003` 为基础进行最小必要改造。

页面应包含：

* 患者信息及当前就诊
* 既往史、用药、过敏和检验
* 病历编辑器
* AI 西医分析
* AI 中医辨证
* 舌象分析
* 处方候选
* AI 结果接受、修改和驳回
* 保存、演示签名、提交 Mock HIS

界面采用白色、浅灰和医疗蓝，清晰区分患者事实、AI 建议、医生编辑的正式文书。

不增加营销型 Dashboard，不先建设大量独立管理页面。

## 六、AI 任务处理

点击分析后，不要让 HTTP 请求长时间阻塞。

优先复用现有后台任务及 SSE 实现；如 SSE 当前不稳定，允许改为后台任务 + 任务状态轮询。

至少展示：

* 正在分析
* 西医分析状态
* 中医分析状态
* 舌象分析状态
* 综合分析状态
* 已完成或部分失败

模块状态必须由真实模型调用及实际处理结果决定。

模型失败时，明确显示失败原因或不可用状态；允许其他成功模块继续展示。

如果当前模型推理耗时仍然较长，记录实测延迟，不得通过假进度、静态结果或隐藏错误来宣称达到性能目标。

## 七、处方和 Mock HIS

AI 只生成处方草稿。

医生可以查看、修改、接受或拒绝草稿。提交 Mock HIS 前必须经过医生确认。

提交操作必须实际写入演示数据库，并保存提交状态、时间、操作者和请求标识。对于重复提交，应避免产生重复处方或重复收费记录。

明确标记这是模拟 HIS，不允许任何代码意外连接真实医院数据库。

## 八、随访闭环

实现最小可用流程：

创建随访计划
→ 添加患者回答
→ 生成随访摘要
→ 评估风险
→ 更新待处理预警
→ 医生查看和处理。

现有高危关键词规则可以继续复用。不要在本轮重新建设大型慢病规则引擎。

## 九、最终验收

必须现场实际执行：

1. 启动现有系统。
2. 初始化 Demo 数据。
3. 打开 `http://localhost:3000/encounters/enc-003`。
4. 上传或选择演示输入。
5. 调用真实模型执行分析。
6. 展示真实返回的西医和中医结果。
7. 完成医生审核及病历保存。
8. 创建处方草稿、确认并提交 Mock HIS。
9. 创建随访、提交患者回答并验证风险预警。
10. 重启 API 后验证患者、就诊、病历、处方和随访记录仍然存在。
11. 模拟一个模型服务不可用，验证剩余页面与 Mock HIS 演示流程不崩溃。

只更新实际需要的代码和配置。

生成 `docs/demo-status.md`，记录：

* 如何启动系统
* 如何初始化 Demo 数据
* 如何复现黄金路径
* 实际调用的模型与端点
* 验证通过的步骤
* 实测分析耗时
* 仍存在的问题
* 哪些功能暂未实现

不要在本轮扩展为完整生产级系统。优先保证一条完整、真实、可重复演示的业务路径。

现在直接检查现有项目，执行必要修改，并运行验收。遇到可局部规避的问题时自行选择最小风险方案，记录假设后继续推进。
