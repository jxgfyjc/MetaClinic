# 象元 AI 诊疗 v3 — 重构日志

## 1. 目标架构

```
浏览器（医师/护士/药师/管理员） ──┐                         ┌── 模型服务（不属于本栈，只读探测）
患者手机（扫码，令牌在 URL #片段） ─┼─ Next.js 15 (apps/web, :3100) ─ rewrite /api/v1/* ─▶ FastAPI (server/, :8011) ──┤ 7870 主模型 Qwen3.8-27B (GPU1)
                                 │                                  单进程 + 进程内任务 worker   │ 7871 中医 ShizhenGPT-7B (GPU1)
                                 │                                          │                    │ 7872 ASR  Qwen3-ASR (CPU)
                                 │                                  SQLite(WAL, FK ON)           └ 7875 OCR  PaddleOCR-VL (CPU)
                                 │                                  data/xiangyuan.db  data/objects_v3/
```

后端分层（`server/`）：`api/`（路由+序列化）→ `domain/`（业务规则，纯函数/服务）→ `db/`（模型+迁移）；横切：`security/`（会话、令牌、权限矩阵、审计链、限流）、`safety/`（处方规则引擎+参考数据）、`ai/`（客户端、事实表、提示词、校验）、`jobs/`（持久化任务队列）、`pdf/`。

## 2. 关键设计决策（及原因）

| 决策 | 原因 / 取舍 |
|---|---|
| **同步 SQLAlchemy 2 + SQLite(WAL)**，不用 async | SQLite 单写者；同步会话在线程池/worker 线程里事务边界清晰，避开 greenlet 坑。代价：单进程部署（已在运行手册中写明） |
| **持久化任务队列**（DB 表 `jobs`/`job_events`），资源池 asr=1 / ocr=1 / llm=1 / light=2 | 旧版进程内 asyncio 任务重启即丢。条件 UPDATE 原子领取、心跳、卡死恢复、重试+退避、幂等键、取消。LLM 串行（实测并发无吞吐收益） |
| **一次就诊 = 一份统筹方案**（`TreatmentPlan`），**处方是独立单据**（`Prescription`，仅有 `plan_id` 单向引用） | 多诊断要统筹用药（避免重复/冲突），而处方是需要签署/药房流转的法律文书，生命周期不同 |
| **过期检测靠哈希**：`inputs_hash`（接诊事实）与 `dx_set_hash`（最终诊断集合）；方案/分析记录生成时的哈希 | 不靠时间戳猜；诊断或资料任何变化都能确定性地发现；确认后的方案遇诊断变化自动退回草稿 |
| **AI 只能引用编号事实表 F1…Fn**，引用不存在的编号直接剔除并计数；无有效引用的诊断标"依据较弱" | 结构性地防止编造"事实"；界面可点开每个引用看原始资料与来源（患者自述/医师/语音转写未核对/OCR 未核对） |
| **安全规则引擎 ≠ AI**：规则版本化（`xy-safety-2026.10.1`）、结果绑定处方内容哈希、签署时**重新计算** | 模型输出不可信（实测 7B 曾写入朱砂）；严重提示需书面理由，警告需确认，必须修改项阻断签署 |
| **病历追加式版本** + 分段 origin（auto/doctor/patient）+ 自动汇总"只建议不覆盖" | 满足"绝不覆盖医师文字"；定稿冻结快照（诊断/方案/处方/检验按 id+哈希引用）+ 签名哈希，之后只能带原因"更正" |
| **服务端可撤销会话**（Cookie `xy_session`，库里只存 sha256）+ **患者作用域令牌**（`X-XY-Token`，哈希存储，种类 intake_link / intake_session / portal） | 取代可伪造的无状态 JWT；患者令牌永远只能触达自己的资料 |
| **权限矩阵 + 职责分离**（`security/permissions.py`） | ADMIN 不能签处方/定稿/审诊断；NURSE 不能诊断/签署；PHARMACIST 只看已签署处方；医师只能访问自己或待接诊池的就诊 |
| **乐观锁 `row_version` + `Idempotency-Key` + 条件更新状态机** | 重复点击/多窗口/并发：处方签署、发药、认领等用 `UPDATE … WHERE status=? AND row_version=?` 原子切换，只有一个成功 |
| **哈希链审计日志** | 篡改/删除可被 `verify-audit` 发现；越权尝试也记录 |
| **序号用原子计数器**（见 §4 的并发缺陷） | 门诊号/就诊号/处方号/病历号 |

## 3. 数据模型与迁移/兼容策略

- 35 张表（患者/过敏/预约/就诊/问诊会话/附件/检验项/任务/分析/诊断/方案/治疗项/处方/病历版本/随访/审计/幂等键/药品…）；外键开启，状态值有 CHECK 约束。
- **版本化 SQL 迁移**（`server/db/migrations/NNNN_name.sql`，语句以 `-- ;;` 分隔）：
  - 已应用迁移的 **checksum 不可变**，每次启动校验；版本号必须从 1 连续。
  - 对**已有数据**的库，应用任何待执行迁移前，用 SQLite 在线备份 API 备份到 `data/backups/`（实测：真实导入后的库升级到 0002 时生成 `xiangyuan-pre-v0002-…db`）。
  - 回滚 = `python -m server.cli restore <备份>`（先停 API）。
  - 当前：`0001_baseline`（由 ORM 生成后冻结）、`0002_number_counters`（并发安全的序号计数器）。
- **旧库兼容**：新库是**新文件** `data/xiangyuan.db`；旧库 `ai_clinical.db` 只读，不做就地改造 → 回退成本为零（旧服务仍可用）。
- **一次性、可重复、只读旧库的导入**（`python -m server.cli import-legacy [--dry-run]`），映射表 `legacy_map` 保证幂等。用真实旧数据在草稿库上跑通的结果：17 患者、15 就诊、39 次分析（作为历史）、17 诊断、7 方案、12 处方、24 个病历版本、7 个随访计划，外键检查干净；5 条找不到归属的随访回答被隔离在 `legacy_map`（不丢、不乱挂）。
  处理过的真实数据问题：同一任务多条回答（每条独立成任务，`submit_key=legacy:<id>`）；同一就诊多份"生效"方案（只保留一份）；已完成就诊上的未签草稿（跳过）；后来才定稿的重复病历（记为 `amendment`）；旧账号携带 bcrypt 哈希，已知默认口令者标记必须改密。

## 4. 本轮浏览器端到端发现并修复的缺陷（真实发生过的）

| 缺陷 | 发现方式 | 修复 |
|---|---|---|
| **序号并发冲突**：`SELECT max()+1` 在两个并发请求下取到同一个号，后者撞 `UNIQUE(mrn)` → HTTP 500（患者端"提交"双击即可触发） | 手机端提交按钮连点，浏览器看到 `POST /p/intake/submit → 500` | 迁移 0002 `number_counters` + 单条 `UPDATE … SET value = MAX(value, :seed)+1`（事务内串行、回滚不留空号）；问诊提交增加**条件更新抢占**（draft→submitted 只有一个请求赢，其余返回同一结果或"提交中"）；全局把漏出的 UNIQUE 冲突映射为 409 而非 500。序号并发测试已验证**在旧分配器下失败、新实现下通过** |
| **过期方案无法"沿用"**：诊断集合变化后，只能重新生成（丢弃医师手工修改） | 走查"改诊断 → 方案过期"流程 | 新增 `POST /plans/{id}/rebase`：医师写明≥5 字理由后重新对齐哈希，内容不动，但退回草稿须重新确认；审计记录前后锚点与理由 |
| **方案里的药物只在最后签署时才校验** | 读代码发现 `plan_gen` 文档承诺"生成后过安全引擎"但并未实现 | 新增 `GET /plans/{id}/safety-preview`（同一规则引擎，只读）；方案页实时显示 |
| **`finalize` 的 `ignore` 能绕过硬阻断** | 阅读定稿逻辑 | `ignore` 只能放行"软提醒"（方案未确认、OCR 未核对）；无诊断/候选未审/方案过期/处方未签这类硬阻断永远不可忽略；放行项写入审计 |
| **预约接口收到带时区时间直接 500**（aware 与 naive 比较） | 浏览器发送 UTC ISO 时间 | 入参统一转 naive-UTC；`day` 按诊所本地日（UTC+8）换算窗口 |
| **药房退回的处方在已定稿就诊上是死路**（医师不能改、不能重签，只能作废） | 推演"定稿后药房退回" | 签署校验：已定稿就诊仍不接受**新**签署，但药房退回过的处方（`review_by` 已设置）可修改并重签；界面提示去"病历"用"更正"同步 |
| **剂量文本可填任何东西**（"5mg10mg"通过校验，界面显示"规则引擎未发现问题"） | 脚本把 `10mg` 追加到 `5mg` 后，截图里出现 "5mg10mg" 且无任何提示 | 新规则 `rx.dose_format`（警告，需确认）：剂量必须形如 5mg / 0.5g / 1片 / 1/2片 / 10-20mg… |
| **保存后的处方永远显示"有未保存修改"，签署按钮一直灰** | 浏览器：新增药味→保存→签署按钮不可用且无原因 | 脏检查改为比较**规范化**字段（编辑器新增行与服务端返回行的多余键不同）；并为"禁用签署"的每种原因显示明确提示 |
| 导航把"运行状态"露给了医师 | 角色走查（侧栏） | 菜单权限收紧为 `job.manage` |
| **乐观锁不是原子的**：5 个携带同一 `row_version` 的并发写入全部成功（静默覆盖，版本号被多次递增） | 场景 3 并行请求 | `check_version` 改为：先取写锁、在锁内重读版本再比较（`acquire_write_lock`）；`Idempotent` 改为“谁插入幂等键谁执行，重复请求等待并重放其结果”（原先靠 0.5 秒时间启发式，同键并发全部执行）；分析 / 方案 / 处方生成 / 建诊在检查前先取写锁。4 个并行回归测试，其中 3 个已验证在旧行为下失败 |
| 一次选多个文件时，第二个文件**被静默丢弃** | 真实模型场景：语音 + 检验单 + 舌象只传上去第一个 | 上传改为排队；`useAction` 在“不同的操作被丢弃”时给出提示（同一操作的双击仍静默合并） |
| **真实 27B 返回了合法 JSON 但没有 `differentials` 数组** → 西医模块失败（`no_candidates`），且失败模块没有保留任何模型原文，无法排查 | 真实模型场景（单独调用同样的提示词是正常的——说明是模型输出的偶发形态） | 接受常见键名/字段名变体（`differential_diagnoses`、`diagnosis` 等）；缺候选时带“重要提醒”**重试一次**；仍失败则**不生成任何诊断**，并把模型原文节选存入模块（界面“运行详情”可展开查看）。3 个回归测试 |

## 5. 前端（apps/web）

- Next 15 App Router + SWR；`(staff)` 路由组共用**一个常驻外壳**（侧栏/顶栏/二维码弹窗不随页面重载）；患者端 `/p/intake`、`/p/portal` 独立极简布局（令牌从 URL `#t=` 读取后立即移入 sessionStorage 并清除地址栏）。
- **诊疗室**（`/encounters/[eid]`）六步：接诊资料（逐字段防覆盖+自动保存+版本冲突处理，语音/检验/舌象并排）→ AI 分析与诊断（"先看这个"→候选与依据→详情三层展示）→ 治疗方案（统筹、过期/沿用、治疗项逐项审核、安全预检）→ 处方（结构化编辑、安全面板、签署/撤回/作废、模拟 HIS）→ 病历（分段、版本、定稿/更正、PDF）→ 随访。已访问的步骤保持挂载，切换不丢未保存内容。
- 统一交互原语：Toast、确认框（可要求书面理由）、骨架/空/错误态、`useAction`（单飞行动作：重复点击被丢弃、失败 Toast、陈旧版本友好提示）。
- 语音：`VoiceCapture` 在安全上下文用 MediaRecorder（音量条、时长、权限/无设备提示），否则降级为"调用手机录音/选文件"并说明原因。
- 检验单：与原图并排的可缩放查看器，逐项核对。
